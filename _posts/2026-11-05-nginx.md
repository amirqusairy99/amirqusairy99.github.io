Encountering expired TLS certificates on web servers is a common challenge in infrastructure troubleshooting. Recently, while working through a [Sad Servers](https://sadservers.com/) scenario, I encountered an Nginx web server configured to serve a "Hello, World!" page over HTTPS with an expired SSL certificate.

Here is a step-by-step walkthrough on how to inspect the system, extract the original Distinguished Name (DN) parameters, generate a fresh self-signed SSL certificate, and restore secure connectivity.

---

## Challenge Overview

* **Description:** An Nginx web server is configured to serve a simple "Hello, World!" page over HTTPS, but the SSL certificate is expired.
* **Task:** Create a new SSL certificate for the Nginx server with the same **Issuer** and **Subject** (same domain and company details).
* **Validation Criteria:**
  1. Certificate must not be expired:
     ```bash
     echo | openssl s_client -connect localhost:443 2>/dev/null | openssl x509 -noout -dates
     ```
  2. Subject must match the original certificate:
     ```bash
     echo | openssl s_client -connect localhost:443 2>/dev/null | openssl x509 -noout -subject
     ```

---

## 1. Initial Reconnaissance & Health Checks

Before updating certificates, it is good practice to inspect active network ports and confirm the status of the web server.

### Check Active Listening Ports
Run `ss` to verify which ports are actively listening:

```bash
ss -tulpn
```

**Output:**
```text

udp    UNCONN  0       0            128.0.0.1:323        0.0.0.0:*

tcp    LISTEN  0       4096                 *:6767             *:*      users:(("sadagent",pid=588,fd=7))
tcp    LISTEN  0       4096                 *:8080             *:*      users:(("gotty",pid=587,fd=6))
```

Port `443` is actively listening, indicating that Nginx is configured to handle HTTPS connections.

### Check Nginx Service Status
Verify that the Nginx service is running normally:

```bash
systemctl status nginx
```

### Test Local HTTPS Endpoint
Test the HTTPS connection using `curl` with the `-k` (insecure) flag to bypass certificate validity errors:

```bash
curl -k https://localhost
```

**Output:**
```html
<!DOCTYPE html>
<html>
<head>
    <title>Hello, World!</title>
</head>
<body>
    <h1>Hello, World!</h1>
</body>
</html>
```

The web server is up and serving content correctly over HTTPS.

## 2. Inspecting the Original Certificate Details

To pass the challenge requirements, the new certificate must replicate the exact **Subject** parameters of the original expired certificate.

Query the live HTTPS endpoint using `openssl s_client`:

```bash
echo | openssl s_client -connect localhost:443 2>/dev/null | openssl x509 -noout -subject
```

**Output:**
```text
subject=CN = localhost, O = Acme, OU = IT Department, L = Geneva, ST = Geneva, C = CH
```

Note down these values:
* **CN (Common Name):** `localhost`
* **O (Organization):** `Acme`
* **OU (Organizational Unit):** `IT Department`
* **L (Locality):** `Geneva`
* **ST (State/Province):** `Geneva`
* **C (Country):** `CH`

---

## 3. Checking Nginx Configuration Paths

Next, inspect the default site configuration to verify the paths for the certificate and private key files:

```bash
sudo nano /etc/nginx/sites-enabled/default
```

Identify the `ssl_certificate` and `ssl_certificate_key` directives in the configuration block. For this setup, we will store our updated keys inside `/etc/nginx/ssl/`.

---

## 4. Generating the New Self-Signed Certificate

Now that we have the exact Subject string and file paths, we can generate a new SSL key pair.

### Step 1: Create the Target Directory
Ensure the target directory exists:

```bash
sudo mkdir -p /etc/nginx/ssl
```

### Step 2: Run OpenSSL Command
Generate a new 2048-bit RSA key and an X.509 certificate valid for 365 days:

```bash
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/nginx/ssl/nginx.key \
  -out /etc/nginx/ssl/nginx.crt \
  -subj "/CN=localhost/O=Acme/OU=IT Department/L=Geneva/ST=Geneva/C=CH"
```

**Command Parameters Explained:**
* `-x509`: Directs OpenSSL to output a self-signed certificate instead of a Certificate Signing Request (CSR).
* `-nodes`: Skips passphrase protection on the key so Nginx can restart automatically.
* `-days 365`: Sets certificate expiration to 1 year from creation.
* `-newkey rsa:2048`: Generates a new 2048-bit RSA key pair.
* `-subj`: Formats the exact Subject attributes retrieved from the original certificate.

---

## 5. Applying Changes & Verification

Restart Nginx to apply the new certificate and private key:

```bash
sudo systemctl restart nginx
```

### Run Verification Commands
Confirm that the certificate dates are active and the Subject details match the original specification:

```bash
# Check validity dates
echo | openssl s_client -connect localhost:443 2>/dev/null | openssl x509 -noout -dates

# Check subject details
echo | openssl s_client -connect localhost:443 2>/dev/null | openssl x509 -noout -subject
```

**Results:**
The certificate is now active, unexpired, and configured with the exact required Subject parameters. Scenario solved!
