## Problem Statement

A user was running Keycloak on an Ubuntu server and needed to enable HTTPS in order to integrate it with other applications. Since this was for an internal/testing environment, a self-signed certificate was acceptable.

---

## Steps Taken

### 1. Check Listening Ports

First, I verified which ports were currently in use:

```bash
netstat -tulpn
```

This confirmed that:
- Nginx was listening on ports **80 (HTTP)** and **443 (HTTPS)**
- Keycloak was running on port **8080**

---

### 2. Check Keycloak Service Status

```bash
systemctl status keycloak
```

Keycloak was already running, but only using HTTP.

---

### 3. Approach Decision

There are two ways to enable HTTPS for Keycloak:

1. Use **Nginx as a reverse proxy with SSL**
2. Use **Keycloak’s native HTTPS configuration**

I chose the first approach (Nginx reverse proxy).

---

### 4. Install Required Packages

```bash
sudo apt update
sudo apt install nginx certbot python3-certbot-nginx -y
```

---

### 5. Generate a Self-Signed Certificate

```bash
sudo mkdir -p /etc/nginx/ssl

sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048   -keyout /etc/nginx/ssl/keycloak.key   -out /etc/nginx/ssl/keycloak.crt   -subj "/CN=192.168.2.38"   -addext "subjectAltName=IP:192.168.2.38"
```

---

### 6. Configure Nginx

Edit the configuration file:

```bash
sudo nano /etc/nginx/sites-available/keycloak
```

Use the following configuration:

```nginx
server {
    listen 80;
    server_name 192.168.2.38;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name 192.168.2.38;

    ssl_certificate     /etc/nginx/ssl/keycloak.crt;
    ssl_certificate_key /etc/nginx/ssl/keycloak.key;

    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    location / {
        proxy_pass          http://127.0.0.1:8080;
        proxy_set_header    Host               $host;
        proxy_set_header    X-Real-IP          $remote_addr;
        proxy_set_header    X-Forwarded-For    $proxy_add_x_forwarded_for;
        proxy_set_header    X-Forwarded-Proto  https;
    }
}
```

---

### 7. Enable and Restart Nginx

```bash
sudo ln -s /etc/nginx/sites-available/keycloak /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
sudo systemctl enable nginx
```

---

### 8. Update Keycloak Service

Edit the service file:

```bash
sudo nano /etc/systemd/system/keycloak.service
```

Update the `ExecStart` line:

```bash
ExecStart=/opt/keycloak/bin/kc.sh start-dev --proxy-headers forwarded --hostname-strict=false
```

Then reload:

```bash
sudo systemctl daemon-reload
sudo systemctl restart keycloak
```

---

### 9. Initial Result

At this point, accessing:

https://{IP-ADDRESS}

worked, but the browser showed a warning (expected for self-signed certificates).

However, a new issue appeared:

somethingWentWrong  
Timeout when waiting for 3rd party check iframe message

---

## Troubleshooting

After some research, I found that this is a **common issue when Keycloak is behind a reverse proxy**.

### Root Cause

Keycloak did not know its public hostname, causing iframe validation to fail.

---

## Fix

### 1. Update Keycloak Configuration

Edit again:

```bash
sudo nano /etc/systemd/system/keycloak.service
```

Update:

```bash
ExecStart=/opt/keycloak/bin/kc.sh start-dev   --proxy-headers xforwarded   --hostname=https://192.168.2.38   --hostname-admin=https://192.168.2.38   --hostname-strict=false   --hostname-backchannel-dynamic=true
```

---

### 2. Update Nginx Configuration

Replace the `location /` block:

```nginx
location / {
    proxy_pass              http://127.0.0.1:8080;
    proxy_set_header        Host                $host;
    proxy_set_header        X-Real-IP           $remote_addr;
    proxy_set_header        X-Forwarded-For     $proxy_add_x_forwarded_for;
    proxy_set_header        X-Forwarded-Proto   https;
    proxy_set_header        X-Forwarded-Host    $host;
    proxy_set_header        X-Forwarded-Port    443;

    # Required for Keycloak iframe / WebSocket
    proxy_buffer_size           128k;
    proxy_buffers               4 256k;
    proxy_busy_buffers_size     256k;
    proxy_http_version          1.1;
    proxy_set_header            Upgrade $http_upgrade;
    proxy_set_header            Connection "upgrade";
}
```

---

### 3. Restart Services

```bash
sudo nginx -t && sudo systemctl reload nginx

sudo systemctl daemon-reload
sudo systemctl restart keycloak

sudo journalctl -u keycloak -f
```

Wait about **30–60 seconds**, then access:

https://192.168.2.38/admin/master/console/

---

## Final Result

The issue was resolved successfully, and Keycloak is now fully accessible over HTTPS 🎉
